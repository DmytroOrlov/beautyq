# BeautyQ search eval v1

This is the first offline benchmark for the Wandsbek/Hamburg seed dataset.

## What this benchmark measures

The primary buyable unit is `MasterServiceOfferVariant`.

Every query contains expectations for exactly three carousels:

1. `variantCarousel` — buyable `MasterServiceOfferVariant` results.
2. `providerCarousel` — nearby `MasterLocation` / provider results with at least one matching variant.
3. `serviceIntentCarousel` — canonical `Service` navigation/refinement results.

The expected blocks are benchmark DSL constraints. They are not meant to be generated by an LLM at runtime.

## V1 scope

V1 contains 63 grounded queries:
- Russian, English, German, and mixed-language queries
- direct queries, synonyms, conversational queries, typos/noise
- hard-negative traps
- price/duration/numeric intent where the seed supports it
- coverage across all 9 services
- coverage across enum, boolean, int, and BigDecimal attribute groups

## Scoring direction

Start with a simple offline scorer:

- +5 if a required variant match appears at top-1
- +3 if a required variant match appears within top-3
- +1 for preferred constraints within top-5
- -5 if a forbidden variant appears within top-10

Provider and service carousels should use lower weights:
- provider top-3 required hit: +3
- provider distance preference: +1
- service intent top-3 hit: +2

The first implementation does not need to be perfect. The goal is to detect regressions.

## Recommended next expansions

1. Add 30–50 real user-like exploratory queries after manual testing.
2. Add misspellings/transliteration: `manikur`, `wimpernverlengerung`, `depilazija`, `shelak`.
3. Add German domain synonyms: `Nagelmodellage`, `Auffüllen`, `Enthaarung`, `Gesichtsbehandlung`.
4. Add negative tests for overloaded words: `gel`, `removal`, `lifting`, `lip`, `correction`.
5. Add distance-sensitive cases once the provider ranking logic is implemented.
6. Add field-level indexing tests for breadcrumbs/facets: category, service, attributes, price buckets.
7. Add “no exact match but useful fallback” cases once the UI fallback behavior is defined.
8. Add query families for future attributes such as `EnumSet` when multi-zone services are modeled.
